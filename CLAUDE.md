# Pills — генератор обоев

Статический сайт без фреймворков. Исходники в `src/`, сборка встроенным бандлером Bun (`build.mjs`) → `dist/`.
Инструменты — только Bun (`bun run …`, `bunx …`); npm/npx/node не использовать.
Подробности структуры и команд — в README.md.

## Ветки и процесс
- **Вся работа ведётся в ветке `dev`.** Перед началом работы: `git switch dev`. Не коммить напрямую в `main`.
- `main` — продакшен. В неё попадает только готовое и проверенное: merge `dev` → `main` и push,
  когда пользователь явно скажет, что всё готово.
- Push в `dev` выкладывает превью на `dev.wallpaper-pills.pages.dev`. Продакшен (`wallpaper-pills.pages.dev`)
  выкладывается только по тегу `vX.Y.Z` (SemVer) на коммите из `main`; push в `main` сам ничего не деплоит
  (GitHub Actions, `.github/workflows/deploy.yml`). Тег ставить, когда пользователь скажет выпустить релиз.

## Перед коммитом
- Сообщения коммитов — на английском, в формате Conventional Commits (`feat:`, `fix:`, `chore:`…).
- `bun run build` должен проходить без ошибок.
- Проверить в браузере через `bun run dev` (http://localhost:8000), если менялся UI или рендер.

## Код
- Без зависимостей: только ванильный JS (ES-модули) и CSS, сборка — средствами Bun. Не добавлять пакеты без явной просьбы.
- `color.js`, `state.js`, `render.js` не трогают DOM (кроме `toCanvas`). DOM — в `main.js` и UI-модулях
  `picker.js` (выбор цвета) и `eyedropper.js` (пипетка).
- Формат ссылок-рецептов (параметры в hash) — публичный: не ломать обратную совместимость старых ссылок.
- В ссылку пишутся только параметры, отличные от `DEFAULTS` (`state.js`). Поэтому значения в `DEFAULTS`
  не менять: короткие ссылки, опирающиеся на умолчания, начнут открываться иначе.
- Интерфейс двуязычный (ru/en): все строки — в `src/js/i18n.js`, в разметке — через `data-i18n*`.
  Новую строку добавлять сразу в оба словаря. Язык хранится в localStorage, в ссылку не пишется.

## Scripts
- `scripts/img2preset.mjs` — восстанавливает пресет (JSON) по PNG-обоям с рядом таблеток: `bun scripts/img2preset.mjs <png>...`.
